## 1. 文档作用

本文只具体化 ver3 中尚未完全可执行的“动态五档留牌体系”。

若本文与 ver3 的手牌资源等级描述冲突，以本文为准。本文不修改：

- 赤献行为；
- 丹恩行为；
- 第一张杀之前的路线决策；
- 锁定目标与连续攻击；
- 换人后的 3/2/1 杀规则；
- 其他角色对血缠和赤献的响应。

`ai_cards.js` 中的过拆/顺手分层是本文的结构参考，但本文不复用其目标评分，也不修改该文件。

## 2. 设计原则

### 2.1 分层决定大方向

```text
Tier 1 > Tier 1.5 > Tier 2 > Tier 3 > Tier 4 > Tier 5
```

Tier 之间使用足够大的固定分差。层内小分只能决定同 Tier 排序，不能跨越 Tier。

### 2.2 不再保留普通杀种子

殷华当前辅助能力很强，不需要为未来爆发无条件保留第一张【杀】。

```text
未形成两杀蓄爆组的所有杀
→ Tier 5
```

### 2.3 最多两张防御牌进入 Tier 1

防御牌仍严格定义为：

```text
闪、桃、酒
```

每次规划时，从当前手牌的防御牌中选出至多两张最重要的牌进入 Tier 1。

- 有两张及以上防御牌：最高的两张进入 Tier 1；
- 只有一张：该牌进入 Tier 1；
- 没有防御牌：不产生 Tier 1 防御资源；
- 第三张及之后的防御牌回到各自基础 Tier。

Tier 1 是资源数量上限，不是必须填满的两个固定槽位。

### 2.4 1 血有缠增加 Tier 1.5

殷华 1 血且有血缠时，原本已经满足 Tier 2 条件的：

- 防具；
- `+1马`；

晋升为 Tier 1.5。

```text
1血有缠
+ 原Tier 2防具或+1马
→ Tier 1.5
```

Tier 1.5 低于两张 Tier 1 防御牌，高于其他结构资源。

### 2.5 两杀蓄爆保留

沿用 ver3 的保守成立条件：

```text
当前攻击范围内存在2血敌方
and 当前手中至少有2张杀
```

满足时：

```text
排序最前的两张杀 → Tier 3
第三张及之后的杀 → Tier 5
```

两张杀不作为绝对不可拆分的原子组：

- 有两个保留位置时优先全部保留；
- 只有一个位置时允许保留其中一张；
- 不为了保持组合完整而空置手牌位置。

## 3. 使用时点与职责边界

### 3.1 UseNowValue 与 KeepTier 分离

```text
UseNowValue
= 一张牌现在是否应该使用，以及应该选择哪个目标

KeepTier
= 一张最终留在手里的牌，弃牌时是否值得保存
```

【过河拆桥】和【顺手牵羊】的即时使用继续交给 `ai_cards.js`。当前能拆除关键装备或创造攻击窗口的牌，应在“明显正收益非杀牌”阶段直接使用。

留牌规划器只处理完成该阶段后仍在手里的牌。

因此：

- 不从留牌函数调用 `bestTargetScore()`；
- 不从留牌函数调用过拆/顺手的 `targetResult()`；
- 不用目标评分反向决定是否保留过拆/顺手；
- 当前未使用的过拆/顺手默认按一般优质锦囊处理。

### 3.2 三次重算

留牌计划在以下时点按真实状态重新生成：

1. 使用完明显正收益非杀牌后，用于首次路线判断；
2. 每使用一张杀后，用于判断剩余杀能否全部保留；
3. 丹恩摸牌完成后，用于本次实际弃牌。

不提前猜测丹恩将摸到的具体牌。

## 4. 规划上下文

每次规划先创建一次只读快照：

```text
KeepContext = {
    hp,
    maxHp,
    hasBlood,
    handLimit,
    handCards,
    equippedCards,
    legalEnemies,
    enemiesInSlashRange,
    hasTwoHpEnemyInRange,
    sameNameIndexes
}
```

资源分类函数只读取该快照和卡牌的直接信息，不在每张牌评分时重新遍历复杂收益链。

## 5. Tier 1：两张核心防御资源

### 5.1 选择顺序

殷华 1 血时：

```text
桃 > 酒 > 闪
```

殷华 2 血及以上时：

```text
桃 > 闪 > 酒
```

同名牌按手牌中的稳定顺序排列，越靠前的副本优先。

取排序后的前两张作为 Tier 1。

### 5.2 1 血无缠

1 血无缠时基础手牌上限通常只有 1。规划器仍可识别至多两张 Tier 1，但最终只能留下其中最高的一张。

```text
1血无缠
→ 唯一手牌位置必定优先留给最高Tier 1防御牌
```

不需要额外创建“只识别一张 Tier 1”的特殊分类分支。

### 5.3 多余防御牌回退

未进入 Tier 1 的防御牌按基础档位处理：

| 牌 | 回退档位 |
|---|---:|
| 桃 | Tier 3 |
| 第一张未晋升的酒 | Tier 3 |
| 额外酒 | Tier 4 |
| 闪 | Tier 4 |

这里的“第一张酒”按整手牌中酒的稳定顺序计算，不因前一张酒进入 Tier 1 而重新产生第二张“第一张酒”。

## 6. Tier 1.5：1 血有缠的防御结构

### 6.1 触发条件

```text
self.hp == 1
and self.hasBlood
```

### 6.2 可晋升资源

只有已经通过 Tier 2 判定的以下资源能够晋升：

#### 防具

- 卡牌属于防具；
- 当前可形成有效防御改善；
- 不是无效、纯重复或明显负面替换。

#### +1马

- 卡牌属于防御马；
- 装备后能够改善至少一名敌方到殷华的距离关系；
- 不是无效重复。

### 6.3 不晋升的资源

以下即使属于 Tier 2，也不因 1 血有缠晋升：

- 武器；
- `-1马`；
- 进攻型距离资源；
- 过河拆桥；
- 顺手牵羊；
- 其他非直接防御结构资源。

### 6.4 理想结果

1 血有缠时手牌上限通常为 3。若资源齐全，保留结果自然表现为：

```text
2张 Tier 1 防御牌
+ 1张 Tier 1.5 防具或+1马
```

若没有 Tier 1.5，再由 Tier 2、Tier 3 依次补位。

## 7. 其余资源基础档位

### 7.1 Tier 2：明确结构质变

保留 ver3 的结构质变定义：

- 有效防具；
- 能让关键敌方从“杀不到”变为“杀得到”的武器；
- 能立即改变关键攻防距离的马；
- 其他能够明确改变当前攻防结构的装备资源。

过拆/顺手的当前战术价值由 `ai_cards.js` 负责立即兑现。它们不因当前可用目标在留牌阶段重复晋升 Tier 2。

### 7.2 Tier 3：强通用与成型资源

包括：

- 【无中生有】；
- 未进入 Tier 1 的【桃】；
- 第一张未进入 Tier 1 的【酒】；
- 满足条件的前两张蓄爆【杀】；
- 当前装备栏空缺、能产生一般改善但没有达到 Tier 2 质变的马；
- 其他已明确列为强通用资源的牌。

### 7.3 Tier 4：一般优质资源

包括：

- 未进入 Tier 1 的【闪】；
- 额外【酒】；
- 【无懈可击】；
- 未在此前使用、仍有一般未来价值的【过河拆桥】和【顺手牵羊】；
- 一般优质锦囊；
- 没有达到 Tier 2 的普通可用装备。

### 7.4 Tier 5：普通、冗余与杀

包括：

- 所有未形成蓄爆组的【杀】；
- 蓄爆组之外的第三张及后续【杀】；
- 无明显用途的普通牌；
- 无效或重复装备；
- 低收益及重复功能资源。

## 8. 数值化表示

为保证层内分不会跨层，使用固定基础分：

| Tier | 基础保留分 |
|---|---:|
| Tier 1 | 1000 |
| Tier 1.5 | 850 |
| Tier 2 | 700 |
| Tier 3 | 500 |
| Tier 4 | 300 |
| Tier 5 | 100 |

层内微调统一限制在：

```text
0 <= tieScore < 100
```

最终分数：

```text
keepScore = tierBase + tieScore
```

### 8.1 静态层内基础值

参考既有 `ai_cards.js` 的安全牌值思想，使用独立静态值，不调用经过殷华修正后的牌值函数：

| 牌或类别 | tieScore 基础值 |
|---|---:|
| 桃 | 80 |
| 无中生有 | 70 |
| 无懈可击 | 60 |
| 过河拆桥 / 顺手牵羊 | 55 |
| 酒 | 50 |
| 一般锦囊 | 48 |
| 一般装备 | 45 |
| 闪 | 40 |
| 杀 | 35 |
| 其他基本牌 | 30 |
| 未知或无明确用途牌 | 20 |

Tier 1 防御牌不直接使用此表，而使用第 5.1 节的体力相关顺序。

### 8.2 同名递减

同名第 `i` 张牌采用：

```text
sameNamePenalty = min(i, 3) * 5
```

其中第一张 `i = 0`，不扣分。

```text
finalTieScore
= clamp(baseTieScore - sameNamePenalty, 0, 99)
```

两杀蓄爆组的前两张杀不因同名递减掉出 Tier 3；递减只决定两者及同 Tier 资源之间的次序。

### 8.3 最终同分

最终分数仍相同时，按手牌中的稳定物理顺序处理，不使用随机数。

## 9. 留牌计划与派生变量

### 9.1 chooseCardsToKeep

```text
function chooseCardsToKeep(hand, handLimit, context):

    1. 创建KeepContext快照

    2. 选出至多两张Tier 1防御牌

    3. 检查1血有缠的Tier 1.5晋升

    4. 检查Tier 2结构资源

    5. 检查两杀蓄爆组，将前两张杀升到Tier 3

    6. 为其余牌分配基础Tier

    7. 计算keepScore

    8. 按keepScore降序排列；同分按稳定牌序

    9. 前handLimit张进入keptCards，其余进入discardedCards

    10. 返回完整计划和每张牌的tier/reason
```

### 9.2 NaturalOverflow

```text
NaturalOverflow
= max(0, hand.length - handLimit)
```

它只表示当前是否自然溢出，不判断具体会弃哪张牌，也不包含尚未发生的丹恩摸牌。

### 9.3 CanKeepAllRemainingSlash

```text
CanKeepAllRemainingSlash
= 当前所有剩余可使用的杀
  是否全部存在于keptCards
```

判断对象是具体【杀】是否能留住，而不是“是否需要弃任意牌”。

## 10. 与 ai_cards.js 的关系

`ai_cards.js` 提供的设计经验：

- 先判断战术层级；
- 使用大分差保证层级支配；
- 只在层内使用小幅倾向分；
- 把距离、装备、判定区等条件拆成纯辅助函数；
- 为未知牌准备安全静态回退值。

本文采用同一结构，但不直接调用其高频目标评分。

允许后续抽取的仅是纯工具或静态数据，例如：

- 卡牌子类型判断；
- 距离变化判断；
- 安全静态牌值表。

禁止从留牌评分中调用：

- `bestTargetScore()`；
- `targetResult()`；
- `get.effect()`；
- `player.getUseValue()`；
- 任何会再次进入殷华 `aiUseful/aiValue` 修正的函数。

## 11. 递归与性能约束

### 11.1 纯分类

同一份 `KeepContext` 中，一张牌的资源等级必须由直接状态唯一决定。

不能在分类过程中：

- 模拟完整出牌阶段；
- 再次调用留牌规划器；
- 通过目标收益反推牌值；
- 修改玩家状态；
- 读取会被自身 AI 修正的动态牌值。

### 11.2 单次计划复用

同一个 AI 选择事件内只生成一次留牌计划，所有候选牌共享该结果。

状态实际发生变化后，丢弃旧计划并重建，不跨事件长期缓存。

### 11.3 防御性递归锁

实现时仍可设置轻量递归锁作为异常保护，但正常路径不得依赖递归深度截断才能结束。

## 12. 示例

### 示例 A：1 血无缠，上限 1

```text
手牌：酒、闪、杀

Tier 1候选顺序：酒 > 闪
最终仅保留：酒
杀为Tier 5
```

### 示例 B：1 血有缠，上限 3

```text
手牌：酒、闪、防具、杀

酒、闪 → Tier 1
有效防具 → Tier 1.5
杀 → Tier 5

最终保留：酒、闪、防具
```

### 示例 C：3 血有缠，上限 5，存在2血敌方

```text
手牌：桃、闪、无中、杀、杀、普通牌

桃、闪 → Tier 1
无中 → Tier 3
两张杀 → Tier 3蓄爆组
普通牌 → Tier 5

最终保留：桃、闪、无中、杀、杀
```

### 示例 D：3 血有缠，上限 5，不存在2血敌方

```text
手牌：桃、闪、无中、无懈、杀、杀

桃、闪 → Tier 1
无中 → Tier 3
无懈 → Tier 4
两张杀 → Tier 5

最终保留：桃、闪、无中、无懈、其中一张杀
```

这里保留一张杀不是因为爆发种子加成，而只是它在两个同档最低资源中通过稳定次序获得了最后一个位置。若存在更高 Tier 的牌，两张杀均可被弃掉。

### 示例 E：存在自然溢出但杀都能保留

```text
上限5，手牌6张
两张杀已形成Tier 3蓄爆组
另有一张Tier 5废牌

NaturalOverflow = 1
CanKeepAllRemainingSlash = true
```

不能仅因需要弃一张废牌就误判为“必须把杀打出去”。

## 13. 首轮测试清单

1. 未形成蓄爆组的第一张杀没有额外资源等级。
2. 范围内存在2血敌方时，恰好前两张杀进入 Tier 3。
3. 第三张杀不会随两杀组进入 Tier 3。
4. 任意状态最多只有两张闪/桃/酒进入 Tier 1。
5. 只有一张防御牌时不会虚构第二个 Tier 1 槽位。
6. 1血无缠、上限1时只保留最高的 Tier 1 防御牌。
7. 1血有缠时，有效防具和有效 +1马从 Tier 2 晋升到 Tier 1.5。
8. 1血有缠时，武器和 -1马不会晋升 Tier 1.5。
9. 过拆/顺手留牌评分不会调用目标评分并产生递归。
10. 同一局面重复计算产生完全相同的保留结果。
11. 存在一张可弃废牌时，不会错误认定两张杀无法保留。
12. 丹恩摸牌后重新生成计划，并按最新真实手牌弃置。

## 14. 增量结论

```text
普通杀不再享有爆发种子地位

两杀只有在范围内存在2血敌方时组成Tier 3蓄爆组

闪、桃、酒中至多两张最高资源进入Tier 1

1血有缠时，Tier 2防具与+1马晋升Tier 1.5

过拆/顺手的即时战术分层继续由ai_cards.js负责

留牌分层只处理非杀牌阶段结束后仍在手中的资源

所有留牌判断使用纯快照、静态层内值和稳定排序
```
