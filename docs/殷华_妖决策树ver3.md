# 鲜血仪葬·殷华（妖）AI 决策树 ver3

> 版本：ver3
> 日期：2026-08-10
> 武将：鲜血仪葬·殷华
> 势力：妖
> 性别：男
> 体力：3
> 状态：行为设计稿已落成，尚未据此恢复殷华自身 AI

---

## 0. 设计目标

ver3 的目标是做一个：

- 行为稳定；
- 容易解释；
- 不依赖复杂连续收益模型；
- 不因高频递归估值而卡死；
- 能体现“丹恩蓄势、集中击穿已有血缠目标”的殷华 AI。

总体采用：

```text
高优先级支配规则
+ 少量离散状态
+ 独立的连续攻击控制
+ 动态五档留牌
```

不追求数学最优。收益接近或无法可靠判断时，默认采用更稳定的丹恩路线。

---

## 1. 技能与机制前提

### 1.1 赤献

每名角色的出牌阶段总共限一次，其可以失去 1 点体力，令其与一名拥有【赤献】的殷华各摸 1 张牌，然后其获得“血缠”。

殷华对自己发动时，两个摸牌对象相同，因此：

```text
殷华失去1点体力
→ 摸2张牌
→ 获得血缠
```

### 1.2 血缠

- 不可叠加；
- 手牌上限 +2；
- 防止下次受到的伤害，然后移去血缠。

### 1.3 殷殇

- 殷华造成伤害时，改为令目标失去等量体力；
- 若目标没有血缠，其随后获得血缠；
- 场上每有一个血缠，殷华出牌阶段使用【杀】的次数上限 +1。

因此：

- 殷华可以绕过已有血缠的防伤；
- 攻击无缠敌人，命中后会为其增加血缠和手牌上限；
- 新产生的血缠可能在本阶段内增加殷华的出杀次数。

### 1.4 丹恩

弃牌阶段开始时，若殷华本回合未使用过【杀】，其可以选择一项：

1. 令一名没有血缠的角色获得血缠；
2. 令一名受伤且拥有血缠的角色回复 1 点体力。

然后殷华摸 X 张牌，X 为结算选项后场上实际拥有血缠的角色数。

丹恩摸牌后仍然进入本次正常弃牌结算。

```text
使用第一张杀
= 放弃本回合丹恩
```

---

## 2. 总体决策结构

殷华的出牌阶段分为四部分：

```text
第一部分：生存与赤献前置动作
第二部分：明显正收益的非杀牌
第三部分：第一张杀之前的路线选择
第四部分：进入攻击路线后的连续攻击控制
```

其中第三、第四部分必须分开：

- 第一张【杀】之前，需要计算放弃丹恩的机会成本；
- 第一张【杀】之后，丹恩已经失去，不再重复扣除丹恩收益；
- 连续攻击只比较继续进攻、保留剩余杀和弃牌之间的关系。

建议将最终实现拆为：

```text
decideInitialRoute()
chooseSlashTarget()
shouldContinueLockedTarget()
decideRetarget()
chooseCardsToKeep()
```

## 3. 其他角色发动赤献

### 3.1 默认行为

```text
if 发动者与殷华为友方
and 发动者没有血缠
and 发动者体力 > 1:
    发动赤献
else:
    不发动
```

即：

| 状态 | 行为 |
|---|---|
| 友方、无缠、发动后不会濒死 | 默认发动 |
| 友方、已有血缠 | 不发动 |
| 友方、1 体力 | 不发动 |
| 敌方殷华 | 默认不发动 |
| 中立或态度不明 | 默认不发动 |

### 3.2 多名殷华

- 每名发动者的出牌阶段总共只发动一次；
- 只选择友方殷华；
- 多名友方殷华并存时，优先态度最高者；
- 同分时使用稳定座次顺序，不随机跳动。

## 4. 殷华自己的前置动作

### 4.1 桃

殷华受伤且有可正常使用的【桃】时，默认先使用【桃】，然后重新检查赤献和当前状态。

不为了让丹恩回复自己而故意不吃桃。

### 4.2 自己发动赤献

```text
if 自己没有血缠
and 自己体力 > 1
and 本阶段赤献尚可发动:
    默认对自己发动赤献
```

典型状态转换：

```text
3血无缠 → 赤献 → 2血有缠，并摸2
2血无缠 → 赤献 → 1血有缠，并摸2
1血无缠 → 不发动，避免进入濒死
```

“3 血无缠”和“2 血无缠”仍然必须保留为后续决策状态，因为可能发生：

- 赤献后，血缠在本回合内被伤害移除；
- 赤献已经达到本阶段次数限制，不能再次发动；
- 回合内回复或其他效果再次改变体力。

因此，自赤献是优先动作，但不能假设路线决策时健康殷华必然仍有血缠。

### 4.3 明显正收益的非杀牌

自赤献结算后，先使用当前明显具有正收益的非【杀】牌，例如：

- 正常可用的过牌；
- 明显有收益的控制锦囊；
- 能改善当前结构的装备；
- 其他不会与杀/丹恩路线发生直接冲突的牌。

每次获得新牌、改变装备、改变距离或改变目标状态后，重新计算路线。

不在本步骤提前使用只能通过【杀】兑现收益的【酒】。

## 5. 核心状态变量

### 5.1 LegalEnemy

```text
LegalEnemy
= 当前能够成为殷华合法杀目标的敌方角色
```

若不存在合法敌方：

```text
不计算 EffectiveSlash
不进入杀路线
→ 有正收益丹恩则丹恩
→ 否则结束出牌
```

### 5.2 Vulnerable（脆弱）

目标满足以下之一时，可暂记为脆弱：

- 当前 0 手牌；
- 当前 1 手牌；
- 最近一次拥有合法出【闪】机会时没有出【闪】，且之后没有获得新牌。

```text
Vulnerable = true
```

补充约束：

- 因不可响应、直击或没有出现合法出闪窗口而未出闪，不记为脆弱；
- 目标获得或摸到新牌后，清除“未出闪”产生的脆弱记录；
- 0/1 手牌产生的脆弱状态始终按当前手牌实时计算。

### 5.3 EffectiveSlash（有效杀数）

只有存在合法敌方后才计算：

```text
EffectiveSlash
= min(
    当前手中可实际使用的杀数,
    当前剩余出杀次数
  )
```

ver3 暂不预测：

- 首杀命中无缠目标后新增血缠带来的额外次数；
- 后续摸牌或其他技能产生的新杀；
- 复杂的剩余火力概率。

上述内容只按实际结算后的最新状态重新计算，不提前加入确定火力。

### 5.4 OverKill（可靠处决窗口）

```text
OverKill =
    EffectiveSlash > EnemyHP
    or
    (
        EffectiveSlash == EnemyHP
        and Enemy.Vulnerable
    )
```

含义：

- 火力多于体力时，可以容忍至少一次常规防御；
- 火力等于体力时，只在目标明显脆弱时视为可靠处决；
- 这是离散的斩杀信号，不是数学保证。

### 5.5 NaturalOverflow（自然溢出）

```text
NaturalOverflow =
    使用完明显正收益的非杀牌后，
    当前手牌数 - 当前手牌上限
```

只取大于 0 的部分。

NaturalOverflow 不计入丹恩尚未摸到的牌。原因是丹恩摸牌后再弃牌仍然提供滤牌收益，不能仅因丹恩制造了溢出就反过来强迫殷华放弃丹恩。

### 5.6 CanKeepAllRemainingSlash

```text
CanKeepAllRemainingSlash
= 按当前五档留牌规则，
  是否能够保住所有剩余可用杀
```

它不等于“是否需要弃任意牌”。

例如，手里有一张明显废牌需要弃置，但两张杀都能保留时：

```text
CanKeepAllRemainingSlash = true
```

不能因此错误进入攻击路线。

### 5.7 TeamHealthy

健康二杀例外使用：

```text
TeamHealthy =
    自己满体力且有血缠
    and 己方不存在1体力角色
    and 己方不存在必须由丹恩立即处理的生存危机
```

### 5.8 DanenBasePositive

丹恩前半段动作本身对己方有明确正收益时为真，例如：

- 给无缠友方增加血缠；
- 回复受伤的血缠友方；
- 按自身状态给自己补缠或回血。

以下情况为假：

- 只能给敌方增加血缠；
- 只能给敌方回复体力；
- 所有友方均满血且已有血缠，自己也无法从选项中获益。

不单纯为了摸 X 张牌而给敌方血缠或回血。

## 6. 第一张杀之前：路线决策

### 6.1 全局前置判断

```text
if no LegalEnemy:
    if DanenBasePositive:
        return DANEN
    return HOLD
```

只有存在合法敌方时，才进入以下状态树。

### 6.2 自己无缠

此时代表：

- 自赤献不能发动；或
- 自赤献本阶段已经发动；或
- 赤献后血缠又在本回合内被移除。

```text
if EffectiveSlash >= 4:
    ATTACK
elif exists OverKill target:
    ATTACK
else:
    DANEN → 给自己血缠
```

### 6.3 1 血有缠

```text
if EffectiveSlash >= 4:
    ATTACK
elif exists OverKill target:
    ATTACK
else:
    DANEN → 自己回复1点体力
```

### 6.4 2 血有缠

```text
if exists OverKill target:
    ATTACK

elif EffectiveSlash >= 4:
    ATTACK

elif EffectiveSlash == 3:
    if exists 有缠合法敌方:
        ATTACK
    elif exists Vulnerable 合法敌方:
        ATTACK
    else:
        DANEN

else:
    DANEN
```

该状态的丹恩目标规则见第 7 节。

### 6.5 3 血有缠

```text
if exists OverKill target:
    ATTACK

elif EffectiveSlash >= 3:
    ATTACK

elif EffectiveSlash == 2
and exists 有缠合法敌方
and TeamHealthy
and NaturalOverflow > 0:
    ATTACK

elif DanenBasePositive:
    DANEN

elif EffectiveSlash == 1
and CanKeepAllRemainingSlash == false
and exists 有缠合法敌方:
    ATTACK

else:
    HOLD
```

解释：

- 丹恩收益很高，普通二杀默认不值得放弃丹恩；
- 只有己方健康、已有血缠目标、且当前自然溢出时，二杀才作为明确例外；
- 丹恩本身没有正收益时，一张本来留不住的杀可以打向有缠敌方；
- 对无缠敌方的一张非斩杀通常宁可弃掉，也不主动给予其血缠和 +2 手牌上限。

### 6.6 四杀强制爆发

只要存在合法敌方：

```text
EffectiveSlash >= 4
→ 强制进入爆发路线
```

四杀不再与普通丹恩收益比较。

## 7. 丹恩目标选择

### 7.1 自己无缠

```text
优先给自己血缠
```

### 7.2 1 血有缠

```text
优先给自己回复1点体力
```

### 7.3 2 血有缠

```text
if 存在1血无缠友方:
    给该友方血缠
else:
    给自己回复1点体力
```

理由：丹恩位于弃牌前，自身回复会使基础手牌上限同步 +1，因此默认自疗的即时收益较旧版结束阶段丹恩更高。只有 1 血无缠友方构成更紧急的保护需求。

### 7.4 3 血有缠

健康殷华无法从自疗中获益，因此按以下顺序选择友方：

```text
1. 1血无缠友方 → 给血缠
2. 1血有缠且受伤友方 → 回复
3. 其他无缠友方 → 给血缠，低体力优先
4. 其他受伤有缠友方 → 回复，低体力优先
5. 没有正收益目标 → 不发动丹恩
```

默认不向敌方赠送血缠或回复体力。

### 7.5 摸牌数

先完成加血缠或回复，再重新统计 X：

```text
X = 当前存活且实际拥有血缠的角色数
```

随后摸 X 张并正常进入弃牌计算。

## 8. 第一刀目标选择与锁定

### 8.1 目标优先级

合法敌方按以下顺序选择：

```text
斩杀目标
> 有缠且脆弱目标
> 有缠目标
> 脆弱目标
> 普通无缠目标
```

同档目标使用以下稳定顺序打破平局：

1. 基础出杀收益更高；
2. 体力更低；
3. 敌方威胁更高；
4. 座次稳定顺序。

不使用纯随机目标选择。

### 8.2 锁定目标

使用第一张【杀】时记录：

```text
LockedSlashTarget
AttackReason
```

只要锁定目标仍存活、仍是敌方且仍可合法成为【杀】的目标，连续攻击优先继续指向同一人。

目的：

- 集中火力；
- 避免同时给多名无缠敌人增加血缠；
- 让命中后获得的“防御薄弱信息”能够被连续利用。

---

## 9. 对锁定目标的连续攻击

连续攻击由独立函数 `shouldContinueLockedTarget()` 控制，不重新计算丹恩收益。

### 9.1 普通攻击路线

```text
上一张杀令锁定目标实际失去体力
→ 继续攻击锁定目标

上一张杀被闪或未造成体力流失
→ 停止普通连续攻击
```

停止原因是目标已表现出有效防御。此时不因为一次被闪就立即把杀分散给其他无关敌方。

### 9.2 处决与四杀爆发路线

以下路线在开火时已经接受消耗防御牌的计划：

```text
AttackReason == OVERKILL
or AttackReason == FOUR_SLASH_BURST
```

因此即使其中一张杀被闪，也继续攻击原锁定目标，直到：

- 目标死亡、离场或不再合法；
- 没有可使用的杀；
- 当前出杀次数耗尽。

ver3 不在此过程中建立新的连续概率模型。

### 9.3 触发换人判断

只有锁定目标：

- 死亡；
- 离场；
- 变为友方；
- 或不再是合法目标；

才调用 `decideRetarget()`。

普通路线因被闪而停手时，不自动换人。

## 10. 换人后的剩余杀决策

换人逻辑只在已经使用过至少一张【杀】、丹恩已经失去之后运行。

```text
N = min(
    当前手中剩余杀数,
    当前剩余可用杀次数
)
```

若没有合法敌方，立即停止。

### 10.1 剩余 3 杀及以上

```text
N >= 3
→ 按目标优先级选择新目标
→ 继续倾泻杀
```

新计划记为剩余火力爆发；每张杀结算后按最新 N 再检查。

### 10.2 剩余 2 杀

```text
if 存在斩杀目标:
    进攻最佳斩杀目标

elif 存在有缠目标:
    进攻最佳有缠目标

elif CanKeepAllRemainingSlash == false:
    进攻当前最佳敌方

else:
    停止并保留2杀
```

### 10.3 剩余 1 杀

```text
if 存在斩杀目标:
    出杀

elif CanKeepAllRemainingSlash == true:
    停止并留手

elif 存在有缠目标:
    对最佳有缠目标出杀

else:
    不出杀，交给弃牌阶段弃置
```

### 10.4 逐张重算

每使用一张杀后重新计算 N 和 `CanKeepAllRemainingSlash`。

例如：

```text
原本剩2杀且两张无法全部保留
→ 使用第一张
→ 现在只剩1杀且可以保留
→ 停止，不机械打光第二张
```

## 11. 动态五档留牌体系

弃牌统一采用：

```text
Tier 1 > Tier 2 > Tier 3 > Tier 4 > Tier 5
```

同一张牌可根据当前局面动态晋升。

### 11.1 Tier 1：当前生存刚需

如果失去某张牌会显著提高殷华近期死亡风险，该牌进入 Tier 1。

主要包括：

- 低血时必须保留的【桃】；
- 缺少有效防御时必须保留的【闪】；
- 低血时用于濒死自救的【酒】。

本设计中“防御牌”专指：

```text
闪、桃、酒
```

### 11.2 Tier 2：结构质变资源

满足当前局面质变条件时进入 Tier 2：

- 当前无防具且可用的防具；
- 能让关键敌方从“杀不到”变为“杀得到”的武器；
- 能立即改变关键攻防距离的马；
- 能拆除关键防具、距离马或阻断资源的【过河拆桥】；
- 能直接获得当前缺失关键装备的【顺手牵羊】。

只在确实发生结构变化时晋升，不按牌名永久固定为 Tier 2。

### 11.3 Tier 3：强通用与成型蓄爆资源

通常包括：

- 【无中生有】；
- 非 Tier 1 状态下的【桃】；
- 第一张【酒】；
- 满足条件的两杀蓄爆组；
- 当前没有对应马时、虽未立即质变但能改善距离的普通马。

两杀蓄爆组成立条件：

```text
当前攻击范围内存在2血敌方
and 当前拥有至少2张杀
```

成立时优先把两张杀作为组合保留。

### 11.4 Tier 4：一般优质资源

通常包括：

- 普通安全状态下的【闪】；
- 第二张及之后的【酒】；
- 【无懈可击】；
- 未达到 Tier 2 质变条件、但仍有稳定用途的锦囊与资源。

### 11.5 Tier 5：普通或冗余资源

包括：

- 当前没有明确用途的普通牌；
- 重复且不能产生额外价值的装备；
- 没有形成蓄爆组的普通【杀】；
- 第三张及之后、当前不能转化为爆发的冗余【杀】；
- 低收益或重复功能牌。

### 11.6 同档排序

同一 Tier 内不进行新的复杂连续估值，采用：

```text
原始牌的 useful
→ 同名牌递减价值
→ 稳定座次/牌序
```

作为平局处理。

不使用纯随机弃牌，以便复测和排查行为。

### 11.7 两杀组合的装箱规则

`TwoSlashBurstGroup` 不是绝对不可拆分：

- 有两个保留槽时，优先整体保留；
- 只剩一个保留槽时，允许保留其中一张杀；
- 不为了维持“组合完整”而空置手牌上限；
- 两张杀是否都能留下，由 `CanKeepAllRemainingSlash` 返回明确结果。

### 11.8 最终算法

```text
function chooseCardsToKeep(hand, limit):

    1. 根据当前局面给每张牌和两杀组合分配最终Tier

    2. 按 Tier 1 → 5 填充保留槽

    3. 同Tier按原始 useful、同名递减价值和稳定牌序排序

    4. 两杀组合在空间足够时整体保留；空间不足时允许拆一张

    5. 超出上限的最低优先级牌弃置
```

## 12. 血缠带来的团队目标偏好

### 12.1 非殷华角色

普通角色面对两个敌方目标时：

- 轻微降低对已有血缠敌人的伤害牌收益；
- 优先攻击没有血缠的敌方；
- 只改变两个敌方之间的优先顺序；
- 不能把原本对敌方的正收益翻转为负收益；
- 直接斩杀始终可以覆盖该降权。

### 12.2 殷华

殷华优先攻击已有血缠敌人，因为：

- 殷殇绕过其血缠防伤；
- 不会再次给予血缠；
- 不会进一步增加敌方的血缠收益；
- 符合团队分工。

血缠目标加权只能影响目标选择，不能独自决定是否放弃丹恩进入攻击路线。

### 12.3 敌方殷华的仇恨

拥有血缠的敌方角色对普通队友的攻击吸引力轻微下降；敌方殷华本人的威胁优先级上升。

该修正同样只做轻度排序，不修改阵营态度正负号。

## 13. 完整伪代码

```text
function playYinhuaTurn():

    usePeachWhenNormallyBeneficial()

    if self.noBlood
    and self.hp > 1
    and selfChixianAvailable:
        useChixianOnSelf()

    useClearlyPositiveNonSlashCards()

    legalEnemies = getLegalSlashEnemies()

    if legalEnemies.isEmpty():
        action = chooseDanenAction()
        return action ? DANEN : HOLD

    state = readCurrentState()
    route = decideInitialRoute(state)

    if route != ATTACK:
        return route

    target = chooseSlashTarget(legalEnemies)
    lock(target, route.reason)
    useSlash(target)

    while hasUsableSlash():

        if lockedTarget.isLegal():
            if shouldContinueLockedTarget():
                useSlash(lockedTarget)
                continue
            return HOLD

        decision = decideRetarget()

        if decision != ATTACK:
            return HOLD

        lock(decision.target, decision.reason)
        useSlash(decision.target)
```

`decideInitialRoute(state)`：

```text
if noLegalEnemy:
    DANEN if DanenBasePositive else HOLD

if self.noBlood:
    ATTACK if EffectiveSlash >= 4 or OverKill
    else DANEN_SELF_BIND

if self.hp == 1:
    ATTACK if EffectiveSlash >= 4 or OverKill
    else DANEN_SELF_HEAL

if self.hp == 2:
    ATTACK if OverKill or EffectiveSlash >= 4

        ATTACK if BloodEnemy or VulnerableEnemy

if self.hp >= 3:
    ATTACK if OverKill or EffectiveSlash >= 3

              and BloodEnemy
              and TeamHealthy

              and not CanKeepAllRemainingSlash
```

## 15. 首轮行为测试清单

### 15.1 赤献

1. 友方 2 血无缠时会对友方殷华发动赤献。
2. 友方 1 血无缠时不会发动。
3. 敌方不会主动向殷华发动。
4. 殷华 3 血无缠时自赤献，变为 2 血有缠并摸 2。
5. 殷华本阶段已经自赤献、血缠随后被移除时，不会错误再次赤献。

### 15.2 丹恩

6. 1 血无缠时，无可靠斩杀则给自己血缠。
7. 1 血有缠时，无可靠斩杀则回复自己。
8. 2 血有缠且存在 1 血无缠友方时，优先给该友方血缠。
9. 2 血有缠且不存在上述友方时，回复自己并获得额外 1 点手牌容量。
10. 3 血有缠且没有正收益友方目标时，不为了摸牌给敌方血缠。
11. 丹恩摸牌后按最新手牌数和手牌上限正常弃牌。

### 15.3 第一张杀

12. 没有合法敌方时绝不因手里有 4 杀而尝试进入杀路线。
13. 无缠或 1 血状态下，除四杀和 OverKill 外优先丹恩。
14. 2 血有缠、三杀且存在有缠目标时进入攻击。
15. 2 血有缠、三杀但只有不脆弱无缠目标时优先自疗。
16. 3 血有缠、两杀、有缠目标、己方健康且自然溢出时攻击。
17. 上述二杀场景无自然溢出时优先丹恩或留手。

### 15.4 连续攻击与换人

18. 普通路线首杀命中后继续攻击锁定目标。
19. 普通路线首杀被闪后停止，不立即把杀分散给别人。
20. OverKill 或四杀爆发路线可以容忍一次闪并继续攻击锁定目标。
21. 锁定目标死亡后剩余 3 杀，继续选择新目标倾泻。
22. 剩余 2 杀且存在有缠目标时继续攻击。
23. 剩余 2 杀、无斩杀/有缠目标且两张都能保留时停手。
24. 剩余 1 杀能留住时停手；留不住且有缠目标时出杀。
25. 剩余 1 杀留不住、无斩杀且只有无缠目标时不出，进入弃牌。

### 15.5 留牌与团队目标

26. 同 Tier 手牌选择可重复复现，不因纯随机改变。
27. 两杀组合在有两个槽位时整体保留，只有一个槽位时允许保留一张。
28. 普通队友在收益接近时优先攻击无缠敌方。
29. 殷华在同档敌方中优先攻击有缠目标。
30. 血缠降权不会把敌方目标的正收益翻转为负收益。

## 16. 行为摘要

```text
无缠且能安全赤献 → 先自赤献

无缠 / 1血 → 强恢复，除四杀或可靠斩杀外保丹恩

2血有缠 → 默认自疗；1血无缠队友优先保护；三杀才明显转攻

3血有缠 → 三杀积极爆发；二杀通常保丹恩，
           仅在己方健康、有缠目标且自然溢出时开火

第一张杀前 → 比较攻击路线与丹恩

第一张杀后 → 不再重复计算丹恩，锁定目标集中攻击

原目标失效后 → 按剩余3/2/1杀、斩杀、有缠目标和可留手情况换人

弃牌 → 动态五档，同档使用基础 useful 稳定排序
```

一句话概括：

> 殷华以赤献建立血缠，以丹恩维持己方血线和资源；只有在可靠处决、三至四杀爆发，或健康溢出且已有血缠目标时，才放弃丹恩集中倾泻火力。
