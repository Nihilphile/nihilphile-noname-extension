# 落绯 AI 行为设计 v1

> 日期：2026-09-14  
> 武将：落绯（`nihil_luofei`）  
> 实现：`nihilphile武将包/module/luofei.js`  
> 状态：首轮实现，等待实战校准

## 1. 设计边界

落绯 AI 只能影响自动决策，不能改变玩家可见或可操作的规则：

- 不修改技能触发时机、发动条件、合法目标、牌的归属或结算结果；
- 真人仍可自由取消【殷潮】、选择消耗数量、决定每张红牌是否使用及选择合法目标；
- AI 只接入 `processAI`、`check`、目标选择 `ai` 和正常弃牌阶段的 `aiUseful`；
- “脆弱”“斩杀”及无闪记录均无可见标记、无技能效果，只供 AI 评分读取；
- 留牌修正只在 `chooseToDiscard` 的直接父事件为本人的 `phaseDiscard` 时生效，不影响响应、主动出牌、交牌和技能代价。

## 2. 核心状态

### 2.1 脆弱 Vulnerable

目标满足任一条件时，视为脆弱：

```text
当前手牌数 <= 1
或
存在仍有效的“有合法出闪条件但被杀命中”记录
```

无闪记录仅在以下条件全部满足时生成：

- 落绯使用【杀】后进入 `shaHit`；
- 该次命中不是直击或整体禁闪；
- 目标当时拥有手牌，并且【闪】可用；
- 受到该次伤害对目标不是正收益。

目标实际获得新手牌后，记录立即清除。0/1手牌产生的脆弱始终实时计算，不依赖记录。

### 2.2 斩杀 OverKill

【殷潮】的红牌已经全部亮出，因此逐张选目标时可以用剩余红牌数作为有效火力：

```text
OverKill =
    剩余红【杀】数 > 目标当前体力
    或
    剩余红【杀】数 == 目标当前体力 且目标脆弱
```

这是可靠处决信号，不是必然击杀保证。

## 3. 【殷潮】资源决策

```text
没有“血”
→ 不发动

没有正收益的合法杀目标
→ 不为赌黑牌单独发动

只有1血：
  ├─ 存在1体力且脆弱的正收益敌人 → 消耗1血尝试斩杀
  └─ 否则 → 保留给流生

至少2血且存在正收益目标
→ 保留1血，其余全部用于殷潮
```

每张红牌单独重新选择目标；没有正收益目标时放弃使用并按规则弃置。

目标只在原本收益为正的合法角色之间按以下信号加权：

```text
斩杀 > 1体力 > 脆弱 > 普通正收益目标
```

这些加权不能把负收益或友方目标翻成正收益目标。

## 4. 【流生】决策

【流生】先支付1血，因此当前血数决定红判定分支：

```text
当前正奇数血（生）
  ├─ 受伤友方或自己 → 发动
  └─ 敌方、中立、未受伤目标 → 不发动

当前正偶数血（息）
  ├─ 敌方 → 发动
  └─ 友方、自己、中立 → 不发动
```

黑色判定获得判定牌只作为附带收益；AI 不为赌黑牌而承担治疗敌人或伤害友方的风险。

自身目标优先按“是否为自己”判断，不依赖 `get.attitude` 的正负；即使混乱或其他态度修正令 AI 对自身态度为负，“息”状态也不会对自己发动。此保护只接入自动决策，不限制真人玩家主动选择。

## 5. 正常弃牌的防御倾向

落绯的回合结束阶段可能通过【殷潮】获得黑牌，而黑色牌中进攻和控制资源较多。因此正常弃牌阶段显著抬高防御资源的保留评分：

| 资源 | 首张基础保留分 | 说明 |
|---|---:|---|
| 桃 | 10.0 | 治疗与救援 |
| 酒 | 1体力时9.8；其他8.8 | 低血线优先自救 |
| 闪 | 9.6 | 核心防伤资源 |
| 无懈可击 | 9.2 | 防止高价值锦囊 |
| 防具（equip2） | 8.6 | 持续防御 |
| +1坐骑（equip3） | 8.2 | 降低被攻击概率 |

同名重复牌按小幅固定值递减，但多张防御牌仍通常高于普通进攻牌。其他牌不由落绯规划器覆盖，继续使用引擎原始评分。

## 6. 工程结构与验证

沿用殷华 AI 的可复用经验：

1. `aiHelpers` 中的脆弱、斩杀、资源消费、流生和留牌计算均为纯函数；
2. 运行时适配层只创建只读快照，再把结果交给引擎 AI 回调；
3. 不在留牌评分中递归调用自身修正后的牌值；
4. 场景测试分别验证纯决策和引擎接线；
5. 首轮不加入概率搜索、牌堆预测或跨回合复杂收益模型。

对应测试：

- `tests/luofei_ai_decision_test.js`：纯决策树；
- `tests/luofei_smoke.js`：AI接线、玩家选择隔离、无闪记录与清除、技能原规则。
