# 结论

在该版本中，推荐监听全局 `gainAfter` 与 `loseAsyncAfter`，并对同一个移动事件做实体牌对象交集：

```js
const lostFromHuojingHE = trigger.getl(huojing)?.cards2 ?? [];
const actuallyGainedByShuai = trigger.getg(shuai) ?? [];
const movedCards = actuallyGainedByShuai.filter(card => lostFromHuojingHE.includes(card));
```

`movedCards.length` 就是本次“霍旌原本位于手牌区或装备区的实体牌，实际进入当前帅手牌区”的张数。大于零时令霍旌摸等量牌。这里应按实体牌对象求交集，不要只检查 `event.source`、`event.giver`、动画字符串或技能名；那些字段不能覆盖夺取、技能转移和聚合移动。

这套判定自然覆盖普通 `give/gain`、`chooseToGive`、技能获得、一次多张以及【借刀杀人】失败后移交武器；同时排除以下情况：

- 牌原本不在霍旌的手牌区或装备区；
- 霍旌的牌最终由其他角色获得；
- 牌在获得流程中被销毁、未成功离开原区域或被改送他处；
- 牌进入帅的装备区、判定区或扩展区，而非通过 `gain` 进入手牌区；
- 霍旌就是帅时“自己交给自己”的规则特例。该特例没有真实移动，应由【协攻】上层直接净摸一张，并让本追踪分支跳过 `shuai === huojing`。

# 文件与行号证据

## 一、引擎原语

1. 目标包版本为 `1.11.3`：`package.json:1-3`。

2. 普通获得事件由 `Player.gain()` 创建，接收者存于 `next.player`，牌存于 `next.cards`，最终执行 `gain` 内容：`noname/library/element/player.js:7959-8007`。该事件提供：

   - `getl(player)`：汇总以本获得事件为父事件的该玩家 `lose` 历史，分别保留 `hs/es/js/...` 和 `cards2`：`noname/library/element/player.js:8027-8062`；
   - `getg(player)`：仅当参数就是本事件接收者且事件未被 `getlx === false` 抑制时，返回事件最终 `cards`：`noname/library/element/player.js:8063-8068`。

3. `Player.give(cards, target)` 不是另一套移动模型，而是调用 `target.gain({ cards, source: this, animate: ... })`，并附加 `giver`：`noname/library/element/player.js:8188-8201`。`chooseToGive` 成功后同样调用 `target.gain(event.cards, player)`：`noname/library/element/content.js:5186-5222`。因此普通交牌和绝大多数技能交牌都进入同一个 `gainAfter` 判定面。

4. `lose` 内容先用玩家当时的 `hejsx` 实际区域校验每张牌；不属于该玩家这些区域的牌会从本次 `cards` 移除：`noname/library/element/content.js:11043-11049`。随后按 DOM 所在区域分别记录手牌 `hs`、装备 `es`、判定 `js` 等：`noname/library/element/content.js:11050-11115`。最终 `event.cards2 = hs.concat(es)`，再把该事件写入玩家 `lose` 历史：`noname/library/element/content.js:11190-11195`。所以 `getl(huojing).cards2` 恰好表示本次真实从霍旌手牌区或装备区离开的实体牌，不含其判定区和扩展区。

5. `gain` 内容会先让原持有者执行子 `lose`：`noname/library/element/content.js:10480-10517`。之后它会把将被销毁的牌、仍未成功离开原持有者区域的牌从 `event.cards` 中删掉，并在结果为空时结束：`noname/library/element/content.js:10524-10550`；还会去掉本来已在接收者手牌区的牌：`noname/library/element/content.js:10573-10583`。余下牌才被插入接收者手牌区：`noname/library/element/content.js:10606-10614`、`10736-10745`。因此 `gainAfter` 时 `getg(shuai)` 是成功进入帅手牌区的最终牌集，而不是最初“打算获得”的输入列表。

6. 聚合事件 `game.loseAsync()` 也原生提供同语义接口：`getl(player)` 汇总父事件为该 `loseAsync` 的全部 `lose` 子事件，`getg(player)` 汇总其全部 `gain` 子事件的最终 `cards`：`noname/game/index.js:945-1012`。`gaincardMultiple` 会先产生源玩家的 `lose`，再为各接收者产生 `gain` 子事件：`noname/library/element/content.js:5427-5436`、`5524-5542`。这些子 `gain` 被设为 `getlx = false`，所以监听 `gainAfter` 不会重复计数；成功移动统一由父 `loseAsyncAfter` 的聚合 `getg` 报告。这与普通 `gainAfter` 组成不重不漏的标准监听组合。

7. `addJudge()` 是单独的 `addJudge` 事件，其 `getg(player)` 明确恒为 `[]`：`noname/library/element/player.js:9013-9097`。本方案也不监听 `addJudgeAfter`，所以霍旌把【乐不思蜀】等牌置入帅的判定区不会被当成“交给帅”。装备事件同样有独立 `equip` 事件且 `getg()` 返回空数组：`noname/library/element/player.js:8929-8952`、`8972-9010`。

## 二、包内规则实现的交叉印证

1. 内置技能【恃术】的文本是“一名其他角色……获得你的牌后”：`character/mobile/translate.js:1021-1022`。其实现正是监听 `gainAfter` 和 `loseAsyncAfter`，读取技能拥有者的 `event.getl(player).cards2`，再与目标的 `event.getg(current)` 求实体牌交集；结算时仍以该交集取得实际牌：`character/mobile/skill.js:5878-5912`。这直接印证了“别人获得你的手牌/装备牌”的官方判法。

2. 内置技能【推诚】的文本是“你交给其他角色牌后”：`character/xianding/translate.js:1139-1140`。其实现同样监听 `gainAfter` 和 `loseAsyncAfter`，用 `event.getl(player).cards2` 与 `event.getg(target)` 的交集判断，并以交集长度作为张数：`character/xianding/skill.js:10872-10897`。这直接印证了本报告推荐的计数表达式。

3. 【借刀杀人】在目标不出【杀】时，筛选目标装备区的武器牌，然后执行 `player.gain(cards, target, "give", "bySelf")`：`card/standard.js:3031-3061`。因此武器牌会被记录为目标的 `es/cards2`，并成为出牌者的 `getg`；若霍旌是交武器者、帅是【借刀杀人】的使用者，交集为该武器牌，军赏摸一张。

# 事件 / API 链

## 普通 `give/gain` 与技能交牌

1. 技能或卡牌调用 `huojing.give(cards, shuai)`、`shuai.gain(cards, huojing, ...)`，或由 `chooseToGive` 成功后调用 `shuai.gain(...)`。
2. `gain` 内容为仍有原持有者的牌创建 `huojing.lose(cards, ui.special)` 子事件。
3. 子 `lose` 按牌离开前的实际区域生成 `hs/es/js/...`，其中 `cards2 = hs + es`。
4. `gain` 内容剔除未成功离开、被销毁、已经在接收者手牌区等无效牌，只把余牌放入帅的手牌区。
5. `gainAfter` 触发时：
   - `trigger.getl(huojing).cards2` 是实际从霍旌手牌/装备离开的实体牌；
   - `trigger.getg(shuai)` 是本事件实际进入帅手牌的实体牌；
   - 两者交集即军赏计数。

## 聚合 `loseAsync`

1. 父 `loseAsync` 产生一个或多个 `lose` / `gain` 子事件。
2. 子 `gainAfter` 因 `getlx = false` 而不会向本方案报告获得牌。
3. 父 `loseAsyncAfter` 用自己的 `getl/getg` 汇总全部子事件。
4. 在父事件上做同一实体牌交集并一次计数，支持一对多、多对一和一次多张，同时避免双触发。

## 【借刀杀人】

1. 帅对霍旌使用【借刀杀人】，霍旌不使用【杀】。
2. 标准牌逻辑取霍旌装备区可获得的武器牌。
3. 执行 `shuai.gain(weapon, huojing, "give", "bySelf")`。
4. 武器同时出现在 `getl(huojing).es/cards2` 与 `getg(shuai)` 中，交集长度为 1，军赏摸一张。

# 确认、推断与未知

## 已确认

- `cards2` 在本版本的 `lose` 事件中严格由 `hs.concat(es)` 生成。
- 普通 `gain` 的 `getg` 返回经过失败/销毁过滤后的最终 `event.cards`。
- `loseAsync` 能分别按玩家汇总真实失去与获得牌。
- 官方已有两个语义相近技能采用 `gainAfter + loseAsyncAfter + getl/cards2 与 getg 的实体交集`。
- 【借刀杀人】失败交武器走标准 `gain(..., source, "give")`，无需为卡名写特判。
- 判定区和装备区的目标落点不是 `gain`，且它们的 `getg` 为空；不给本方案计数。

## 有证据支持的推断

- 不应要求 `event.giver === huojing` 或动画是 `"give"`。移动事实已由实体交集证明，省略这些附加条件才能覆盖【顺手牵羊】式夺取、技能强制获得等“其他原因把霍旌自己的牌给到帅”的情况。
- 不应在结算时额外要求牌仍由帅持有。`getg(shuai)` 已记录它确实进入过帅的手牌；若后续 `gainAfter` 技能立刻再移动该牌，仍不应抹掉已发生的这次交牌。
- 如果移动在到达帅之前被合法改道，最终接收者不是帅，`getg(shuai)` 为空；如果原获得事件中的牌未成功离开或被销毁，它会从最终 `event.cards` 删除。两种情况都不会误计。

## 未知 / 本报告不承诺

- 第三方扩展若直接操作 DOM、调用 `directgain/directlose` 或自行伪造历史，可能绕过标准 `gain/loseAsync` 事件；这不属于引擎支持的通用技能触发面，无法仅靠标准触发完整追踪。
- 未做联机实跑；不过所用 API 均来自目标包引擎与内置联机兼容技能。仍应在最终整包测试中至少跑一次联机或双端同步验收。
- `draw(num)` 与循环 `num` 次 `draw(1)` 的最终摸牌数相同，但会产生不同数量的摸牌事件。若冻结规则要求“每张交牌对应一个独立摸牌事件”，上层应循环 `await huojing.draw()`；若只要求摸等量牌，可一次 `await huojing.draw(num)`。这不是牌移动识别接口的差异。

# 最小伪代码

以下只表达 RC-05 的追踪子技能；`resolveCurrentShuai()` 和自帅【协攻】净摸一由上层负责：

```js
junshang_transfer: {
  trigger: { global: ["gainAfter", "loseAsyncAfter"] },
  forced: true,

  getIndex(event, huojing) {
    const shuai = resolveCurrentShuai();
    if (!shuai || shuai === huojing) return [];
    return [shuai]; // 固定本次牌移动发生时的帅，避免结算中途重新解析
  },

  filter(event, huojing, _name, shuai) {
    if (typeof event.getl !== "function" || typeof event.getg !== "function") {
      return false;
    }
    const lost = event.getl(huojing)?.cards2 ?? [];
    const gained = event.getg(shuai) ?? [];
    return gained.some(card => lost.includes(card));
  },

  async content(event, trigger, huojing) {
    const [shuai] = event.targets;
    const lost = trigger.getl(huojing)?.cards2 ?? [];
    const moved = (trigger.getg(shuai) ?? []).filter(card => lost.includes(card));
    if (moved.length) await huojing.draw(moved.length);
  },
}
```

实现时不要再附加 `trigger.source === huojing`、`trigger.giver === huojing`、`trigger.animate === "give"` 或具体技能/卡名过滤；这些都会缩窄“所有原因”的已确认规则。若担心非标准事件重复同一实体引用，可在 `moved` 上用 `Set` 防御性去重，但目标引擎的标准移动事件本身按实体牌数组计数，内置技能也直接使用交集长度。

# 版本风险

- 本结论锁定 `package.json` 为 `1.11.3` 的该份子琪懒人包。其他版本可能调整 `cards2` 字段、聚合事件的 `getlx` 抑制或 `getIndex` 参数约定，升级后须复核上述锚点。
- `getl/getg` 是该版本内置技能广泛使用的事件方法，但 `cards2` 仍是实现字段而非跨版本稳定协议；不要把本报告直接外推到另一分支。
- `containsSome` 是本项目扩展的数组方法；伪代码使用标准 `some/includes`，减少扩展环境加载顺序风险。
- 上层应保证“帅”唯一且能在移动触发建立时得到稳定对象。若帅在同一 `gainAfter` 触发队列中被其他效果更换，使用 `getIndex` 固定的 `event.targets`，不要在 `content` 中再次查当前帅。
