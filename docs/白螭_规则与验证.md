# 白螭 2.0.2 规则与验证

2026-11-06。白螭 `nihil_baichi`，称号太素司生，女性，神势力，基础体力及体力上限均为1。立绘沿用用户提供的原始 PNG，设计署名 lviphylla。

## 生域与龙佑

生域为持恒技，游戏开始时获得3层龙佑；重复入场通知不会重复发放。开局当前体力为4、体力上限为1、龙佑为3层。

龙佑直接计入 `player.hp`，所以技能直接读取当前体力、调用 `getHp()`、比较体力大小时都包含龙佑。`maxHp` 独立，不添加龙佑。通常手牌上限随当前体力计算，开局为4；不再另加一次龙佑，已有改变手牌上限的技能仍按引擎规则生效。引擎原有 `getDamagedHp()` 仍返回上限减当前体力，溢出时可为负值。

生域在场时，所有角色回复体力可超出上限。回复先补足当前体力与上限之间的差额，其余每点增加一层龙佑。例如2/4回复3点，结果为5/4、1层龙佑；已有5/4再回复2点，结果为7/4、3层龙佑。命祀的回复也遵守此规则。

受伤或流失体力，先消耗龙佑，再损失基础体力；当前体力只扣除一次。护甲按原规则先抵挡伤害。实际伤害记录和受伤触发不因龙佑抵挡而消失。直接移除龙佑同步减少当前体力，减少体力上限只截断基础体力，不消耗龙佑；体力上限降至0仍死亡。

**删除所有“场上每移除一层龙佑，生域持有者摸牌”的效果。**

生域只放行通用的满体力回复拦截、满体力使用桃和桃园结义的满体力跳过检查。青囊等技能明确要求“已受伤”的条件、牌禁用、禁止目标和效果排除仍由引擎判断。无体力角色沿用原规则。

体力区追加青绿色高亮勾玉，区分龙佑和普通体力。悬浮说明显示当前体力、体力上限、基础体力及龙佑；有潜鳞时也列出潜鳞。普通体力槽保留缺失状态，龙佑超过8层显示精确层数，上限大于5的原生数字体力条追加数值标签。隐藏武将和无体力状态不展示龙佑勾玉。

## 命祀

锁定技，白螭造成的所有真实伤害均执行替代，包括杀、伤害锦囊、属性伤害和无牌的技能伤害。将造成N点伤害时，防止之，改为令受伤角色减少N点体力上限，再回复2N点体力。N取伤害末段的修正值，在护甲扣除之前确定。伤害先被其他效果防止或降至0时，不执行替代。上限降至0而死亡的角色不再回复。

替代不消耗护甲或已有龙佑，不生成实际伤害及受伤记录。例如4/4的角色承受白螭1点伤害，改为上限降至3、基础体力截至3，再回复2点，最终5/3、2层龙佑。原本1/4则最终3/3、没有新龙佑。

白螭的伤害牌对某目标被抵消时，比较双方**当前体力（包含龙佑）**：白螭严格小于该目标则回复1点，否则摸1张牌，二者互斥。相等走摸牌分支。每次、每名目标分别结算，不设每牌或每回合次数限制；同一个牌效果事件的重复通知只结算一次。

杀被闪抵消及伤害锦囊被无懈抵消，采用原生 `shaMiss` / `eventNeutralized`；南蛮被杀、万箭被闪完整抵挡时，通过原生 `chooseToRespondAfter` 检查对应牌效果的剩余响应需求，补齐引擎没有抵消通知的路径。需要多张响应牌时，只在最后一张成功响应后奖励一次，部分响应后仍命中不奖励。只接收真实牌效果所属的目标响应，过滤无懈交互过程的重复信号。一般目标排除不当作抵消。被其他技能撤销的抵消不发奖励。

每个目标、每次额外结算分别执行上述检查，即使共用同一张牌，也不合并奖励。未响应、响应失败或不可响应而命中时，只执行原有伤害替代，不额外给白螭回血或摸牌。

## 裁生

出牌阶段先流失X点体力，X为本回合此前发动次数，首次0，随后1、2、3……额外出牌阶段不重置，回合结束后重置。代价可以消耗自己的龙佑，代价致死时停止后续。

支付代价后，再选择一名仍有龙佑的在场角色，可选择自己。移除其全部龙佑，记实际移除层数为N；支付代价消耗掉的层数不计入N。若仅自己有龙佑且支付后不会剩余龙佑，不能发动。被选择者本回合无法成为白螭使用的伤害牌的目标，包括本次杀、决斗、南蛮和万箭。非伤害牌不受裁生限制，仍须满足牌本身的目标条件；自选裁生后仍可对自己用桃，桃园结义也可作用于被裁生的角色。

随后**可选**视为使用一张普通杀。无视通常杀次数且不计入次数，至多N个目标，每个目标与白螭的当前游戏距离须不大于N。通常攻击范围不再限制这张杀，长武器也不能把距离上限扩大到N以外；牌禁用、禁止目标仍生效。选择结束后再次检查目标。取消出杀或无合法目标，不撤销移除和目标限制。

受影响者显示“裁”标记，说明列出本回合不能对其使用伤害牌的来源。重复选择同一角色不会重复列出来源，多名白螭分别记录；重新获得龙佑不移除提醒，回合结束后清除。

## 实现范围

`module/longyou_hp.js` 借鉴本地 Zus 包少帝·颛阳的虚拟体力思路，在扩展运行时适配原生 `changeHp`、`recover`、`loseMaxHp` 和玩家刷新方法，保留现有刷新包装；源码文件不改动。龙佑增减与体力增减在原生结算位置配合，避免先换成标记后丢失回复数值。满体力桃与桃园结义的兼容位于 `module/baichi.js`。

适配同时识别少帝的 `zus_qianlin_bonus`，保留其临时体力上限空间；不复制潜鳞的回合末撤销规则，龙佑按自身规则存在。兼容范围以工作区 Zus 参考版本为准。

## 验证

在电脑版和安卓版源码上分别运行：

```sh
node tests/baichi_engine_test.js
NONAME_ENGINE_ROOT='../子琪源码/安卓版' node tests/baichi_engine_test.js
node scripts/test_portable.cjs
```

两份引擎均通过46项白螭检查，包括44项核心检查和2项本地 Zus 参考加载顺序检查；参考文件不在仓库时，这2项明确跳过。20个既有便携测试脚本通过。

白螭检查加载原生事件队列、事件编译器、玩家体力方法及体力结算、`Player.update/$update`、标准杀、南蛮、万箭、桃与桃园结义结算、牌合法性过滤。DOM 节点、触发器筛选、网络、响应选择及用牌外围流程由测试适配。数值检查包含龙佑直接体力读取、手牌上限、护甲、流失体力、溢出回复与 `recoverAfter`、减少上限、命祀全部伤害替代、闪、南蛮与万箭完整响应及无懈事件、严格小于比较、重复及多目标抵消、裁生支付顺序、可取消杀、距离、次数与提醒生命周期。

高亮显示检查执行原生刷新方法，验证勾玉节点、缺失的普通体力槽、隐藏状态和大层数数值；这不等同于浏览器实景外观验收。Zus 检查执行实际参考模块在 Nihil 之前和之后加载的数值路径，验证叠加体力不会被刷新截断；未执行两包完整界面联动对局。

未执行浏览器完整对局、安卓实机导入、真实联机、重连及实战 AI 调优，不把源码组件检查当作实机通过。

## 2.0.1 修复证据

用户报告南蛮目标打出杀后不回血也不摸牌。旧测试只手工发送 `eventNeutralized`，没有覆盖真实南蛮响应流程；原生南蛮和万箭成功响应不会发送该通知。新增测试执行真实南蛮内容：三个目标均响应，预期白螭摸2张并回复1点；修复前实际摸0张，断言失败。修复后在两份源码上通过。新增覆盖万箭、连续两张完整响应、部分响应失败、无响应、不可响应、多目标杀及同一张牌对同一目标的额外结算。修复不改变“仅被抵消时奖励”的触发条件。

## 2.0.2 裁生目标限制调整

裁生仅禁止伤害牌指定被清空龙佑的角色，按引擎 `damage` 标签判断。技能说明与“裁”标记同步更新。沿用已有46项检查，目标合法性断言改为验证杀、决斗、南蛮和万箭仍被禁，桃园结义及自选后的桃不再被裁生阻止。
