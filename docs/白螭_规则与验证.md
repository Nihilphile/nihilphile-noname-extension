# 白螭规则与验证

2026-11-06，新增白螭 `nihil_baichi`，称号太素司生，女性，神势力，1点体力上限。技能为生域、命祀、裁生。立绘采用用户提供的原始 PNG，作者署名沿用技能图中的 lviphylla。

## 生域

生域是持恒技。游戏开始时白螭获得3层龙佑，重复的入场通知不再发放。

所有角色的溢出回复均转化为该角色的龙佑，每点对应一层。生域生效期间，满体力角色也能正常对自己使用桃。无体力的角色保留引擎原有规则。

生域只取消通用的满血回复拦截，技能原有的已受伤发动或目标条件保留。角色的真实满血和受伤状态查询不变。桃园结义不再提前跳过满体力目标，满体力目标回复的1点转为一层龙佑，受伤目标照常补充体力。

受伤和体力流失均优先消耗龙佑，余量才扣除体力。护甲先抵挡伤害，龙佑抵扣剩余的实际扣血。龙佑不减少伤害事件的数值，不取消受伤事件及其后续触发。减少体力上限造成的体力截断不消耗龙佑。

每移除一层龙佑，每名在场且拥有生域的角色各摸一张牌。移除多层合并为一次摸等量牌。龙佑转移不触发移除或摸牌。

每层龙佑令持有者的手牌上限增加1。白螭开局1点体力和3层龙佑，手牌上限为4。获得、消耗、转移和清空龙佑后，手牌上限按当前层数重新计算。

引擎在回复触发器运行之前，就用 `recover.filterStop` 阻止满体力回复。模块对 `Player.prototype.recover` 增加一次包装，仅在生域生效时放行此检查。桃的使用条件也按生域是否生效动态放行。桃园结义的 `ignoreTarget` 在生域生效时放行满体力目标，使原生回复流程得到执行。原本的禁用牌、禁止目标和牌效果排除检查仍由引擎处理。子琪源码未修改。

## 命祀

命祀是锁定技，只在白螭的杀将造成伤害时执行替代效果。

白螭的杀将造成N点伤害时，命祀防止此伤害，改为令受伤角色减少N点体力上限，然后回复2N点体力。N取伤害结算末段的数值，在扣除护甲和龙佑之前确定。伤害先被其他效果防止或降为0时，不再执行替代效果。此效果不消耗目标现有的护甲或龙佑，也不产生实际受伤记录。

回复先恢复实际体力，只有超出减少后的体力上限的部分才转为龙佑。例如1/4体力的角色受到白螭的一点杀伤害时，改为体力上限减至3，再回复2点体力，最终为3/3体力且没有新龙佑。若原先为4/4体力，则减上限后为3/3体力，回复的2点全部转为龙佑。

体力上限降至0而死亡的角色不再执行后续回复。裁生生成的杀同样适用命祀，多目标逐人结算。旧版成为目标时的二选一和龙佑转移已删除。

## 裁生

出牌阶段可选择任意有龙佑的在场角色，包括白螭自己。代价按同一回合内此前发动次数递增，依次为0、1、2。额外出牌阶段不重置代价，回合结束后重置。

先支付流失体力的代价，再清空目标剩余的全部龙佑。代价也能由白螭自己的龙佑抵扣并触发摸牌。若代价令白螭死亡，后续效果停止。

被清空龙佑的角色本回合不能成为白螭使用的牌的目标，包括桃和本次裁生生成的杀。限制在移除龙佑引发的摸牌前生效，其他角色仍可对该目标使用牌。

被裁生影响的角色显示临时“裁”标记。说明列出本回合不能对其使用牌的白螭，直接读取裁生的目标限制记录。重复影响不会重复列出同一来源，多名白螭的来源分别显示。目标重新获得龙佑时保留标记，回合结束后移除。标记只作提醒，不增加规则限制。

随后视为使用一张无实体材料的普通杀，至多选择此次移除层数的目标。选择遵循攻击范围和禁止目标规则。此杀无视次数限制且不计入使用次数，不消耗普通出牌杀的额度。没有合法目标时，移除、摸牌和目标限制仍然生效。

## 验证结果

`node tests/baichi_engine_test.js` 通过38项检查。默认引擎位置为工作区 `子琪源码/电脑版`，也可通过 `NONAME_ENGINE_ROOT` 指定另一份引擎根目录。

测试直接加载该引擎的 `GameEvent`、`GameEventManager`、事件编译器、体力相关玩家方法和结算内容、标准杀的结算内容，以及原生牌合法性检查。测试适配了触发器选择、界面、网络、闪的使用选择和使用牌外围流程，不能替代浏览器或安卓实机验收。

检查覆盖满体力桃、部分回复、伤害和流失体力、护甲、濒死、多名生域持有者、普通移除、裁生自选、0起步代价、多出牌阶段、回合状态重置、目标限制、攻击范围、多目标杀、命祀联动和代价致死。完整扩展加载、立绘和拼音注册也通过检查。

1.2.2使用原生杀的结算验证闪避与命中分支，覆盖两张闪完整抵消、只使用一张闪而命中、跳过闪响应、刺杀的额外弃牌、伤害修正、护甲与已有龙佑、其他来源、其他牌、先行防止伤害、减上限致死，以及同一张裁生杀分别闪避和命中的两个目标。回复检查区分受伤目标的实际回血和溢出龙佑。

1.2.3的次数检查覆盖尚未使用杀、已使用0、1及3次四种状态。每种状态连续发动两次裁生后，普通杀的次数统计均不变，裁生自身的递增代价仍累计。

1.2.4使用原生使用牌的逐目标结算和桃园结义内容验证满血叠龙佑、受伤回血、效果被排除、无体力角色及生域失效后的原生行为。另直接检查原生青囊的已受伤目标条件和正常的满血状态查询均未改变。

1.2.5删除杀被闪抵消后白螭回复体力的效果。原生结算检查覆盖满血及受伤的白螭、双闪、刺杀，以及同一张裁生杀分别被闪避和命中的两个目标，确认闪避不再给白螭回血或增加龙佑，伤害替代仍然生效。

1.2.1新增原生 `getHandcardLimit()` 检查，验证龙佑变化后的手牌上限。裁生标记检查覆盖目标提醒、来源说明、自选、重复影响、多名来源及回合结束清理。界面标记由测试适配，实机外观未验证。

`node scripts/test_portable.cjs` 的20个既有便携测试脚本全部通过。1.2.0开发时使用同一电脑版引擎运行 `tests/mabaoguo_behavior_test.js` 的13项检查通过，1.2.2未重跑该脚本。其余原生测试和性能测试未运行。
