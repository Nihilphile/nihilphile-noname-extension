## 二、AI 决策总览：一条请求从触发到决定的全链路

### 核心结论：AI 判断的本质是"评分排序 + 阈值比较"

```
【触发点】技能/系统调用 player.chooseToUse() / chooseToRespond() / chooseBool() / chooseCard() / chooseTarget()
         ↓ 传入 .set("ai", fn) / .set("ai1", fn) / .set("ai2", fn)
【分发层】library/element/content.js 的事件处理器
         ↓ event.isMine()? 人工操作 : (event.result = "ai")
【执行层】event.result == "ai" 时：
         - chooseToUse/chooseToRespond: 依次调用 ai.basic.chooseCard(event.ai1) 和 ai.basic.chooseTarget(event.ai2)
         - chooseBool: 直接 event.ai(event.getParent(), player) 返回布尔
         - chooseCard: 调 ai.basic.chooseCard(event.ai)
         - chooseTarget: 调 ai.basic.chooseTarget(event.ai)
         - chooseControl: 调 event.ai(event.getParent(), player) 返回选项索引
【循环层】ai/basic.js 的 chooseCard/chooseTarget/chooseButton
         ↓ 获取所有可选牌/技能/目标 → 逐个运行 check 函数打分 → 选最高分
         ↓ 如果最高分 ≤ 0 且非强制，放弃选择 → 返回 false → ui.click.cancel()
【评分层】check 函数内部大量依赖 get.effect / get.effect_use / get.attitude / get.value / get.order / get.useful
         ↓ 这些函数读取 lib.card[name].ai 和 lib.skill[name].ai 字段来微调分数
【缓存层】library/cache/cacheContext.js
         ↓ 所有 get.xxx 在 AI 执行期间被代理，相同参数返回缓存值，防止重复计算
```

## 四、常见 ai 字段写法详解

### 4.1 技能 skill 的 ai 字段

技能定义中 `ai: { ... }` 对象可以包含以下字段：

| 字段 | 类型 | 作用 | 典型值/示例 |
|------|------|------|-----------|
| **result** | Object/Function | 核心：描述技能对 player 和 target 的效果 | `{ player: 1, target: -1 }` 或函数 |
| **effect** | Object/Function | 修正 effect 计算中的乘数 | `{ player(card, player, target, result) { return [0.9, 0]; } }` 或 `{ target: function(...) { return 1.5; } }` |
| **threaten** | Number/Function | 威胁倍数（影响 target 侧判定） | `1.5` 或 `function(player, target) { return ... }` |
| **order** | Number/Function | 出牌优先级（越高越早出） | `3.2` 或函数 |
| **tag** | Object | 标签集合，供 `get.tag(item, tag)` 查询 | `{ respondSha: 1, damage: 1 }` |
| **useful** | Number/Array/Function | 牌在手牌中的有用程度 | `[5, 3, 1]` 表示第1张5分，第2张3分... |
| **value** | Number/Array/Function | 牌的绝对价值 | 同 useful 格式 |
| **expose** | Number | 暴露身份倾向（0~1） | `0.1` |
| **halfneg** | Boolean | 半负面技能标记 | `true` (让 AI 在人少时不触发) |
| **neg** | Boolean | 纯负面技能标记 | `true` (AI 尽可能不触发) |
| **maixie** | Boolean | "卖血"技能标记 | `true`（AI 不主动弃牌挡伤） |
| **maixie_hp** | Boolean | "卖血减上限"标记 | `true` |
| **maixie_defend** | Boolean | "卖血防御"标记 | `true` |
| **nolose** | Boolean | 标记该技能不会导致失去牌 | `true` |
| **noh** | Boolean | 标记该技能不依赖手牌 | `true` |
| **noe** | Boolean | 标记该技能不依赖装备 | `true` |
| **nodiscard** | Boolean | 标记该技能不需要弃牌 | `true` |
| **combo** | Array | 组合技列表 | `["jizhi", "qicai"]` — 告诉 AI 这些技能搭配使用 |
| **canLink** | Function | 铁索属性传导判定 | `function(player, target, card) { return {...}; }` |
| **modAttitudeFrom** | Function | 修正 from 对 to 的态度 | `function(from, to, att) { return att; }` |
| **modAttitudeTo** | Function | 修正 to 收到的态度值 | `function(from, to, att) { return att; }` |
| **equipValue** | Number | 装备价值 | `6` |
| **rejudge** | Boolean | 标记技能可以改判 | `true` |
| **subplayer** | Boolean | 标记为随从技能（子玩家） | `true` |
| **skillTagFilter** | — | 不是 ai 字段，是 `hasSkillTag()` 消费的字段 | 见下文 |

### 4.2 effect 字段的返回值格式

`ai.effect` 可以是以下形式：

- **数字**：直接乘到 result 上。如 `effect: 1.5` → 效果 ×1.5
- **函数**：`function(card, player, target, result, isLink) { return ... }`
  - 返回 `数字` → 乘数
  - 返回 `[乘数, 加数]` → result = result × 乘数 + 加数
  - 返回 `[乘数, 加数, 目标乘数, 目标加数]` → 同时影响两个方向
  - 返回 `"zeroplayer"` → player 侧效果归零
  - 返回 `"zerotarget"` → target 侧效果归零
  - 返回 `"zeroplayertarget"` → 两侧归零
- **对象**：`{ player: fn, target: fn, player_use: fn, target_use: fn }`
  - `player`/`target` 给 `get.effect()` 用
  - `player_use`/`target_use` 给 `get.effect_use()` 用

### 4.3 event 的 ai/ai1/ai2 字段

调用 `player.chooseToUse({ ... }).set("ai1", fn).set("ai2", fn)` 时：

- **ai1(card)**：评分函数，对每张候选牌/技能打分（数字），AI 选最高分
- **ai2(target)**：评分函数，对每个候选目标打分，AI 选最高分
- **ai(...)**：单一评分函数（chooseBool、chooseControl、一些 chooseCard 场景），返回布尔或选项
- **ai.order**：在默认 ai1 实现中被读取（`content.js` 行 56-62），如果 info.ai.order 存在就用它，否则返回 1

### 4.4 卡牌 card 的 ai 字段

卡牌定义中 `ai: { ... }` 典型的完整示例（以 sha 为例，`card/standard.js` 行 275-484）：

```javascript
ai: {
    // 应变效果（特殊机制）
    yingbian(card, player, targets, viewer) { return baseScore; },
    // 铁索传导条件
    canLink(player, target, card) { return { odds: 0.65, num: 1 }; },
    // 基础属性
    basic: {
        useful: [5, 3, 1],    // 手中第1张价值5，第2张3，第3+张1
        value: [5, 3, 1],     // 同上
    },
    // 出牌优先级
    order(item, player) { return 3.2; },
    // 效果描述
    result: {
        target(player, target, card, isLink) {
            return odds * effect;
        },
    },
    // 标签
    tag: {
        respond: 1,
        respondShan: 1,
        damage: 1,                    // 或 function(card) { return 1; }
        natureDamage(card) { return 1; },
        fireDamage(card, nature) { return 1; },
    },
}
```

### 4.5 关键 tag 标签（供 `get.tag(item, tag)` 查询）

| 标签名 | 含义 | 消费位置 |
|--------|------|---------|
| `respondShan` | 此牌可当闪响应 | effect/effect_use 中调整空手牌目标判定 |
| `respondSha` | 此牌可当杀响应 | 同上 |
| `respond` | 此牌可响应 | 通用响应标记 |
| `damage` | 此牌造成伤害 | effect 中判断 |
| `draw` | 此牌摸牌 | effect 中判断 |
| `recover` | 此牌回复 | effect 中判断 |
| `loseHp` | 此牌流失体力 | effect 中判断 |
| `natureDamage` | 属性伤害 | effect 中触发铁索传导 |
| `fireDamage` | 火属性 | 属性伤害细分 |
| `thunderDamage` | 雷属性 | 属性伤害细分 |
| `valueswap` | 装备替换标记 | equipValue 中判断 |

### 4.6 AI 被"否决"的机制

在 `get/index.js` 行 ~2014-2036，`filterCard` 逻辑中：
- `ai.neg`：标记为负面技能，AI 自动跳过（除非无法跳过）
- `ai.halfneg`：半负面，条件性跳过
- `ai.combo`：组合技白名单，列表内的技能即使不在当前事件中也被视为可用
- `ai.threaten`：威胁值，影响目标选择时"是否值得打这个目标"

## 六、"人机是怎么做到自己判断的"——一句话总结

**AI 不"思考"，而是"打分"。** 任何选择（牌、技能、目标、是/否）都被转化为一个数字评分函数。引擎遍历所有可选项，逐个运行评分函数，选最高分。评分函数内部再通过 `get.effect`（效果值 × 态度 × 威胁 × 对手血量/手牌等修正因子）算出最终分数。所有中间结果被 CacheContext 缓存以避免组合爆炸。技能设计者只需在 `ai` 字段里声明该技能的数值影响（result/effect/threaten/order 等），AI 引擎自动叠加到最终评分中。
